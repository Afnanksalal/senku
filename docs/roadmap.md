# Proposed delivery sequence

Status: engineering sequence for the confirmed full-platform ambition. Requested target: 2026-10-24; not a guarantee of same-day production completeness. See launch-brief.md. No product milestone is implemented.

| Phase | Deliverable | Exit evidence |
|---|---|---|
| 0. Knowledge foundation | Source archive, product/architecture/contracts, rules and decision inventory | All 31 source sections covered; contradictions visible |
| 1. Resolve foundational choices | Confirmed launch scope, coherent schema, runtime/result contracts, reviewed first model, design tokens and stack decisions | Decisions recorded; model equations/units/tolerances reviewed; no placeholder approval |
| 2. Shared local vertical slice | Learner-selectable catalog entry and an internal Enzyme Explorer implementation slice, real local worker, plots, Lab continuity, progress and provenance | End-to-end working result/replay; reference tests; responsive accessible flow |
| 3. Offline proof | Cached local lesson pack, IndexedDB events and reconnect reconciliation | Disconnected completion and exactly-once credit effects; truthful remote state |
| 4. Controlled remote computation | API/persistence/queue, supervisor, numerics adapter, artifacts and cancellation | Isolation/quota tests, diagnostics, timeout/retry behavior and reproducibility export |
| 5. Evidence-grounded Discover | Source connector, bounded sweep, typed tasks, analysis/critic/report | Real jobs, real sources, run-linked claims, failed/offline cases |
| 6. Expanded scientific demo | Approved pathway/RoadRunner workflow and sourced Molecule Museum; other adapters incrementally | Per-engine format/compatibility and scientific checks; no implied universal support |
| 7. Post-learner-launch educator workflow and hardening | Reviewed-template authoring, assignment/progress, deployment/monitoring/recovery | Role/ownership checks, assignment round trip, restore evidence, mobile/accessibility QA |

Real-time collaboration and private share links belong to the learner launch and must be developed alongside shared run/state contracts. Public community/remixing and classroom tools follow later. Subscriptions, new subject domains and every optional native adapter are not automatically launch prerequisites. Advanced models and visualization must pass their own gates rather than block a useful local lesson.

## Immediate next work after knowledge review

Use the confirmed launch brief, settle remaining engineering contracts including collaborative state/roles, author a coherent scientific model, then build integrated learner-to-Lab flows without imposing a mandatory first experiment. Do not begin with an ornamental landing page or install every scientific package before a model needs it.
